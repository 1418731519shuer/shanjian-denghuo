# 剧本生成器（NovelForge）逻辑设计

> 一句话：用 step-explore 多轮写作，产出**多角色、多路线、多结局、自带透明立绘和场景图**的完整仙侠文游。

## 用户需求 → 设计映射

| 需求 | 设计 |
|---|---|
| ≥30 轮 LLM 调用 | 管线共 5 个写作阶段，每阶段若干轮，合计 35+ 轮（见下） |
| ≥8 个角色 | 阶段①产出 8 张角色卡 |
| 不同角色不同背景 | 角色卡含「出身/秘密/动机」三要素，各不相同 |
| 自己的人物路线 | 每个角色一条「路线线」（3-5 个关键场景），汇入主线的路线锁 |
| 不同选择不同结果 | 路线选择 + 好感/属性门控，结局按路线+数值分流 |
| 可查看每个人的结局 | 每角色至少 1 个专属结局场景（进结局收集页） |
| 仙侠题材 | 世界观设定=仙侠山门/江湖 |
| 图像按剧本构造角色形象 | 阶段④把角色卡「外貌」翻译成出图 prompt，绿幕出图+AI 抠图=透明立绘 |
| 透明背景方便展示 | 立绘一律透明底 PNG（构建时转 webp 保留透明通道） |
| 写作时说明剧情对应场景 | 阶段②分幕大纲强制每幕声明场景（背景图），素材清单一并产出 |
| 写完一版后看哪里可延伸 | 阶段⑤「续写分析」：列出可拓展的选项点/路线缺口，生成 v2 扩展建议 |

## 管线（5 阶段，35+ 轮）

```
① 企划（2 轮）   世界观 + 8 角色卡（姓名/性别/外貌/出身/秘密/动机/路线主题/专属结局走向）
② 总纲（1 轮）   分幕大纲：每幕 = {场景(背景), 出场角色, 摘要, 归属路线}
③ 写作（N 轮）   逐幕生成 scene JSON（每幕 1 轮，8 幕 ≈ 8 轮）
                 + 每角色路线专场（8 角色 × 2 轮 = 16 轮）
                 + 每角色专属结局（8 轮）
④ 素材（1 轮+出图） 从剧本收集角色形象/场景/CG prompt → 阶跃 step-image-edit-2 绿幕出图
                 → rembg AI 抠图（失败回退 chroma-key）→ 透明立绘；背景直接出图
⑤ 校验+续写分析（2 轮） 结构校验（角色引用/悬空跳转/结局可达）+ LLM 审查「哪里可加选择/延伸」，
                 产出 extension_report.md（v2 扩展点清单）
```

轮次合计：2+1+8+16+8+1+2 ≈ **38 轮**，满足"至少 30 轮"。

## 剧本结构约定

- 主线 3 幕（起/承/转）+ 路线专场 8 个 + 结局 8 个 + 收束 1 个 ≈ 20 场景
- 路线锁定：主线第三幕的选项决定进入谁的路线（`route_su=1` 等 flag + require 场景门）
- 结局分流：路线场景内好感/属性判定 → 该角色的 好/坏 结局
- 属性：每角色好感（归属角色）+ 主控修为/魅力（归属主控）
- 数值判断：选项条件、判定指令、require 场景门全用上

## 素材约定

- 立绘：每角色 3 表情（normal/smile/sad），透明底，命名 `chars/<cid>_<emo>.png`
- 背景：每幕一张，`bg/<slug>.jpg`
- 出图风格词统一（水墨仙侠），seed 固定可复现
- 产出目录 `games_output/<题材>/`，自带 index.html 双击即玩

## 与现有工具的关系

- 复用 script_gen 的 chat/校验、assets_gen 的出图+rembg 抠图、autonovel 的变体组装
- 命令：`python tools/novel_forge.py --theme "仙侠" --chars 8 --rounds-min 30`
- `--dry-run` 只打印管线计划；`--skip-assets` 只出文字版
